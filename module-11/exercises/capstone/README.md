# Capstone: the motorway release

On 2 November the first motorway service areas go live. This release adds them and runs the pricing
service the way a server should. `compose.yaml` is the stack as project `m11x1`, proxy on
`127.0.0.1:8795`, running `127.0.0.1:5001/brightlane/pricing:1.4.0`. `motorway.sql` adds the 60
motorway sites and their tariffs (made by `generate_motorway.py`); `migrate.sh` is the migration job,
which now runs every `.sql` file it finds in `/migrations/`.

1. **Cut the release.** Start the lab registry (`docker compose --profile registry up -d --wait`) and
   build `app/` as `127.0.0.1:5001/brightlane/pricing:1.4.0` for `linux/amd64` and `linux/arm64`, with an
   SBOM and provenance, pushed to the registry.
2. **Write the production file.** Copy `start/compose.prod.yaml` into this folder and fill it in: the
   motorway migration, and everything module 9 to 11 taught a server needs. `tools/readiness.py m11x1`
   must pass all its checks.
3. **Run the drill.** The check stops the stack while the worker writes a month's statement for every
   site, and starts it again: the job must finish, and nothing may be lost.

Start it the way the check does:

```bash
docker compose -f module-11/exercises/capstone/compose.yaml -f module-11/exercises/capstone/compose.prod.yaml up -d --wait
```

The database password file, `.lab/m11x1/db_password.txt`, is generated by the check when it's missing.

Check: `python -m pytest module-11/exercises/capstone`. Clean up afterwards:
`docker compose -f … -f … down -v`, `docker compose --profile registry down -v` and
`docker image rm 127.0.0.1:5001/brightlane/pricing:1.4.0`.
