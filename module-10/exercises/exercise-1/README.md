# Exercise 10.1: Lock it down

`compose.yaml` is lesson 10.1's stack as project `m10x1`, proxy on `127.0.0.1:8794`. Copy
`start/compose.hardened.yaml`, a colleague's first attempt, into this folder
(`module-10/exercises/exercise-1/`) and fix it, so that with both files:

- the API, the worker and the proxy run with a read-only root filesystem, no capabilities they don't
  need (`cap_drop: [ALL]`, and only what a service can't start without added back), and
  `no-new-privileges`;
- seccomp keeps its default profile;
- the stack starts healthy, the API and the worker can write temporary files, a quote through the proxy
  works and the worker completes a statement job.

Start it the way the check does:

```bash
docker compose -f module-10/exercises/exercise-1/compose.yaml -f module-10/exercises/exercise-1/compose.hardened.yaml up -d --wait
```

The database password file, `.lab/m10x1/db_password.txt`, is generated by the check when it's missing;
`python3 -c 'import secrets; print(secrets.token_urlsafe(18))' > .lab/m10x1/db_password.txt` does the
same (after `mkdir -p .lab/m10x1`).

Check: `python -m pytest module-10/exercises/exercise-1`. The check runs `up -d --wait`, reads each
container's settings with `docker inspect`, writes a temporary file in the API and the worker, posts a
quote and queues a statement job. Clean up afterwards: `docker compose -f … -f … down -v`.
